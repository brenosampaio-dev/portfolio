# Relay visual direction — approved correction

**Date:** 2026-10-08
**Status:** Approved for implementation

## Decision

The three generated dashboard directions from the first exploration were
explicitly rejected. None is an implementation target and none may appear as
product evidence.

The approved direction is a code-led **Editorial Operations Index** governed by
the portfolio root `design.md`.

## Accepted qualities

- rigorous 12-column alignment;
- varied 64/128/192px editorial rhythm;
- paper and ink as the dominant surface;
- vermilion used only for the decisive action or urgent exception;
- work queue treated as an index rather than a generic admin table;
- selected exception treated as a focused dossier;
- chronological, source-labelled evidence;
- one clear action hierarchy;
- minimal surfaces, hairlines, and negative space instead of nested cards;
- existing DM Sans/Cormorant/system-mono typography and existing motion.

## Rejected qualities

- three simultaneous dashboard panels;
- card-within-card composition;
- ornamental filters, pills, badges, and KPI blocks;
- excessive rounding or floating surfaces;
- decorative orange;
- generic analytics and invented metrics;
- generated UI presented as proof of a working product;
- any new font or motion behaviour.

## Intended Relay structure

1. A concise operational header and explicit synthetic-data disclosure.
2. A wide exception index with ownership, risk, evidence, and next action.
3. A focused exception dossier opened from the index.
4. A chronological evidence ledger inside the dossier.
5. A resolution area that exposes permission and consequence before action.
6. A compact audit record after closure.

## Evidence rule

Published interface images must be captured from the implemented prototype.
The rejected generated directions are archived only as failed exploration and
must not be committed as active design artifacts.
